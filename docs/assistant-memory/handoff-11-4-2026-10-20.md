Two findings from on-demand routine run 5's red-team pass on the WASM file capabilities (full text: `HANDOFF.md` §11.4).

**ROOT-RESOLVE-1 (RW 4.72, D-V2-167):** every containment check canonicalized the capability's ROOT afresh, so a narrowed
or sub-minted handle whose directory was swapped for a link went where the link went, on BOTH engines. A file capability now
carries its `anchor` (the resolution made at mint or narrowing); no use resolves the root again.
**Why:** a check that resolves both sides at use time decides on whatever the root became.
**How to apply:** for each containment check, ask which side is resolved when, and whether the side treated as fixed is
really fixed. Never soften back to "re-resolve and compare".

**DWX-FLAGS-1 (RW 3.19):** `delulu run FILE.dwx` took its own route and read only four flags; `--broker daemon` and
`--lease` ran under no custody, silently. Now `APPLIED_TO_A_DWX` refuses every other flag (exit 2).
**How to apply:** for every command, list each route its dispatcher can take and keep an allowlist of flags per route,
never a list of refusals. Related: [[a-field-fed-by-a-global]], [[two-name-tables-one-scope]].
